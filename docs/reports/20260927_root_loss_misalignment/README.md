# root loss 与 Root MAE / Global MPJPE 的对齐诊断

2026-09-27。回答「root 权重 ×30 后 Root MAE / Global MPJPE 反而变差，
当前 root loss 到底有没有对齐测试指标」。只做诊断与测量，没有修改训练、
checkpoint、配置或正在运行的 run。

## 更正：位置损失并非"看不见漂移"

初版（同日更早）把结论写成「整个目标对水平平移 + 朝向严格不变，因此累积漂移不可见」。
前半句作为「损失值对整段样本的刚体变换不变」成立，但**推不出后半句**。在 p>0 的
反馈分支里，锚点取自模型自己生成的帧，target 却是用该锚点把 **GT 世界轨迹**变换到
局部系（`train.py:195`），模型输出又用同一锚点变回世界（`generate.py:78`）——同一个
刚体变换两边抵消，因此 `‖p̃−p̃*‖ = ‖P_world − q_world‖`，**位置类损失在数值上就是
该片段的世界系误差**。真正的机制是：

- **(a) δ 不在输入里**：历史被归一化到自身最后一帧，锚点相对 GT 的偏移 δ 不出现在
  输入中；同一输入对应不同 target → 回归病态，模型只能学对 δ 的折中。
- **(b) 目标不可达**：δ 是以「目标位移」形式塞进 target 的（含 −Rᵀδ）；要在一个
  8 帧窗口里补回 δ，而评估末端 δ≈58 cm、单段行进仅约 10 cm。实测（第 8.2 节）
  训练好的模型对 δ 几乎不做任何局部补偿（首帧位移 1.74→2.00 cm），因此位置残差
  ≈ δ，损失按 δ² 上升却**没有可达的下降方向**——加大权重只是在这个不可改变的
  残差上加压。注意：早先推测的「位置项与速度项梯度对抗」**已被实测否定**
  （`cos(root_position, joint_velocity)=+0.55~+0.60`，方向一致）。
- **(c) 训练 δ ≪ 评估 δ**：训练最多 3 段自反馈（约 10 cm 量级），评估到 58 cm。
- **(d) 杠杆监督最弱**：决定 δ 增长的是全局朝向（20–32°）与沿轨推进（−70 cm），
  两者分别只有权重 1 和被 22 关节平均稀释的监督。

下面第 2 节已按此改写；第 0 节标题下的一句话结论中「在数学上不等价」应读作
「位置目标 = 世界误差，但以不可观测、不可达、与速度先验冲突的方式给出」。

## 0. 结论摘要

现在被 ×30 的 `root_position` 监督的是一个
「以本片段自身历史帧为原点、水平朝向对齐、只覆盖 8 帧」的**局部、逐帧、MSE
位置**；而 Root MAE / Global MPJPE 是「以 episode 世界系为准、跨 15–24 个片段
累加」的量。二者的差别不是「看不见 vs 看得见」，而是：位置目标虽然等于片段的世界系
误差，却把累积偏差以「目标位移」的形式塞进 target，而该偏差既不在输入里、也无法在
8 帧内补回（详见上方更正）。
实测分解显示：把「预测的局部运动」换成 GT 局部运动、锚点不变，root ADE 几乎不
变（35.6 → 35.9 cm / 25.4 → 26.9 cm）；反过来把「锚点/世界位姿」换成 GT、局部
运动不变，root ADE 立刻降到 9.0 / 7.9 cm。也就是说**约 75% 的指标误差来自
跨片段累加的世界位姿与朝向，而 ×30 的项只作用在剩下的约 25%，且这 25% 在
训练里已经只剩 1.1–8.4 cm**。因此继续加大该权重不可能改善指标；实测该权重
把 teacher 梯度份额从约 0.7% 提到 6.6%（feedback 下 19.4%），代价是把容量
推向「每段相对自己锚点的绝对位置」，反而加大了段边界跳变（占末帧误差
18–29%）与横向抖动。

## 1. `root_position` 实际优化的对象

代码：`moreact/losses.py` `diffusion_motion_losses()`：
`terms['root_position'] = F.mse_loss(physical[..., TRANSL], target_physical[..., TRANSL])`，
其中 `physical = prediction * std + mean`、`target_physical = target * std + mean`，
`TRANSL = slice(0,3)`（276 维特征的前 3 维，SMPL-X 平移）。参考系由
`geometry.reference_frame(history)` 给出：原点 = **该窗口最后一个历史帧**的骨盆
关节位置（z 置 0，即地面高度保留），x 轴 = 该帧两髋连线在水平面的投影方向，
z 轴 = 世界上方向。

| 问题 | 事实 |
| --- | --- |
| 位置 / 速度 / 位移？ | 逐帧**位置**（`transl`），不是速度或位移；速度只由 `joint_velocity`（权重 100，22 关节平均）间接覆盖 |
| 绝对还是相对？ | **相对**：原点 = 本窗口最后一帧历史；不是 episode 首帧，也不是世界原点 |
| 维度 | x/y/z 全 3 维；z 相对**地面**（原点 z 置 0），因此 z 是绝对高度，x/y 是相对锚点的水平位置 |
| 是否含朝向？ | **不含**。朝向由独立项 `root_orientation`（权重 **1**）与 `root_angular_velocity`（权重 10）承担，且两者都在同一锚点系内比较（只约束窗口内相对转动） |
| 归一化？ | 先反归一化回物理米，再算 MSE：`weighted = 30 × ||Δpelvis||²/3`，即 **≈ 10 × (3D 误差[m])²** |
| 30× 在物理尺度的含义 | 1 cm 误差 → 1.0e-3；10 cm → 0.10（≈ 整个 latent MSE）；30 cm → 0.90。训练/验证里实际只出现 **1.1 cm（teacher）/ 8.4 cm（rollout）**，即该权重从未在指标所处的 30–70 cm 量级上被激活 |
| 锚点在训练时来自哪里 | p>0 的反馈分支（`train.py:229-243`）把生成段反变换回世界再喂回 `context`，因此下一段的锚点来自**模型自己生成的帧**；但 pred 与 target 仍共用这一锚点 |

补充：训练监督视野是 `data.primitives: 4` → **只有 32 帧**；评估是 120（本报告口径）
到 192 帧。

## 2. 与测试指标的逐项对齐

评估（`moreact/evaluate.py:16-47`）在**世界坐标**上：
`root_ade = mean_t ||P_t - Q_t||`（骨盆关节，逐帧），`root_fde = ||P_119 - Q_119||`，
`world_mpjpe = mean_{t,j} ||P_tj - Q_tj||`，
`root_aligned_mpjpe = mean ||(P_t - P_t,pelvis) - (Q_t - Q_t,pelvis)||`。
rollout（`moreact/generate.py:56-84`）每 8 帧用一个新锚点
（`reference_frame(state.reactor_history)`，历史来自生成）把局部预测反变换回世界并累加：

    P_t = P_anchor(m) + R_anchor(m) · p̃_t           (anchor 由生成帧导出)

因此世界位置 = Σ_m R_m Δ_m，指标里的误差是**沿时间的积分**；而训练里的量是
每个窗口自己的 p̃ 与 p̃* 之差。三点结构性不等价：

1. **位置目标 = 世界误差，但 δ 不在输入里、且要求 8 帧内补回**：窗口在
   `condition_window()` 中被归一化到自身最后一帧，pred 与 target 共用同一
   origin/basis（`train.py:190-196`），所以位置类损失等于该片段的世界系误差；
   但累积偏差 δ 是以「目标位移」形式进入 target 的（含 −Rᵀδ），而 δ 不出现在模型
   输入中（同一输入对应不同 target），并且要在一个 8 帧窗口里补回 δ（评估末端
   δ≈58 cm vs 单段行进≈10 cm）。速度类项（joint_velocity 等）在同一锚点系内差分，
   对 δ 不变，因此 δ≠0 时位置项与速度项互相矛盾。
2. **逐帧 vs 轨迹**：损失是帧级 MSE 的平均，无累计项；误差在指标里是
   Σ_m R_m ε_m，逐段误差会累加，且朝向误差会随行进距离放大。
3. **视野**：监督 32 帧，指标 120–192 帧；实测 root ADE 三个 40 帧块为
   10.7 → 37.4 → 58.5 cm（gpu467），超线性增长，说明存在系统性分量而非纯随机游走。

另外存在一个**可辨识性**问题：p>0 时锚点是模型自己生成的（带有未知偏移 δ），
而输入历史又被归一化到该锚点自己的最后一帧 → 同一个输入在不同 δ 下对应不同
target（target 里含有 −Rᵀδ 的位移）。模型既看不到 δ，又被要求复现含 δ 的 target，
于是只能学到一个折中；这正是「段内误差随 rollout 从 0.8 cm 涨到 55 cm」这类
复合退化的直接机制，而不只是笼统的分布漂移。

## 3. 实测分解（40 episode × 120 帧，seed 0，guidance 1）

单位 cm。gpu467 = `diffusion_scratch_b768_root30` step 8500（root_position=30）；
gpu0123 = `diffusion_stage2_b512_stratified` step 21000（无 root_position 项）。
两者 init / 曝光 / batch / curriculum 不同，**本表不隔离权重效应**，只描述现象与
误差来源结构。

| 量 | gpu467 | gpu0123 |
| --- | ---: | ---: |
| root ADE（世界） | 35.55 | 25.40 |
| root xy ADE / z MAE | 33.99 / 4.81 | 23.96 / 4.46 |
| 损失可见的段内局部 root 误差（同锚点系） | 7.86 | 6.73 |
| **GT 局部运动 + 预测锚点 → root ADE** | **35.91** | **26.86** |
| **预测局部运动 + GT 锚点 → root ADE** | **9.00** | **7.86** |
| 边界帧步长 / 段内步长 | 5.45× | 5.72× |
| 朝向绝对误差（末 40 帧） | 21.2°（32.5°） | 19.9°（28.2°） |
| 末帧误差 | 66.83 | 42.99 |
| 沿轨误差累计（Σ(v−v*)·û*） | −70.36 | −70.80 |
| 轨迹长度 预测 / GT | 165.2 / 104.0 | 169.4 / 104.0 |
| 边界速度误差累计（占末帧误差） | 30.41（29%） | 17.91（18%） |
| 朝向不一致导致的漂移 | 29.09 | 26.39 |

读法：
- **局部预测几乎不影响指标**（换 GT 局部运动不改善），**全局位姿决定指标**
  （换 GT 锚点后误差降到 ~9 cm）。×30 优化的正是前者的子集。
- 两个模型**沿轨累计误差几乎相同（−70 cm）**：模型在 GT 的行进方向上只完成约
  1/3 的推进，而在其他方向上多走了路（轨迹长度 +60%，其中约 76 cm 来自 14 次
  边界跳变）。这是「看着在动、位置却越来越偏」的直接解释。
- 朝向漂移（末段 28–33°）单独就能带来约 26–29 cm 的位置误差，它与前一条共同
  构成漂移主因，而它们的权重只有 1 和 10，且都在锚点系内（看不到全局朝向）。
- 首帧误差仅 0.24 cm → 误差确实是**累加**出来的，不是初始条件错。

结论：×30 让 `root_position` 从约 0.7% 变成 teacher 6.6% / feedback 19.4% 的梯度

## 5. 建议的诊断协议（按性价比排序）

1. **受控 A/B（决定性）**：同一 checkpoint、同一 schedule、同一 p，只改
   `root_position ∈ {0, 30}`，各训 1000–2000 步，跑同一 40ep×120 帧协议。
   现在拿到的差异全部混着 init / 曝光 / curriculum，不能归因给权重。
2. **视野实验**：监督视野 32 → 128 帧（`primitives: 4→16`，或加多视界累计位移项），
   验证"看不见长视野"是否是主因。
3. **Oracle 条件替换**（工具已在 `scripts/diagnose_root_error.py`）：GT history /
   自身 history × GT root 平移 / 预测 root 平移 × GT 朝向 / 预测朝向，逐项定位
   平移与朝向的贡献；已有证据（root_attribution：teacher 1.06 cm vs rollout 25.4 cm）
   说明条件退化占主导。
4. **可观测量实验**：把「相对 rollout 起点的累积位姿」作为额外输入（或在推理时
   保留固定参考系），使漂移**可观测**；这是让 world-frame loss 有意义的前提。
5. **评估口径细分**：报告里拆开 root xy-ADE、z-MAE、朝向误差、边界跳变，
   不要只报一个合成 root ADE。

## 6. 推荐的 metric-aligned loss

    L = λ_pose·L_pose              # 现有局部项（feature/FK/velocity/bone/foot），保留
      + λ_disp·L_disp              # Σ_t Huber(Δp_root,t − Δp*_root,t)：专用 root 位移，不被 22 关节平均稀释
      + λ_traj·L_traj              # Σ_h w_h·L1(|P_{t0+h}−P_t0| − |P*_{t0+h}−P*_t0|)：多视界累计位移，直接打击 −70 cm 沿轨欠进
      + λ_world·L_world            # episode 世界系下的生成轨迹 L1（利用 p>0 分支已累加的世界轨迹）
      + λ_heading·L_heading        # 世界系朝向/髋轴误差 + 跨段角速度连续性（当前朝向权重仅 1）
      + λ_boundary·L_boundary      # Huber(v_first − v_last)：跨段速度连续性，抑制 5× 边界跳变

要点：把 `root_position` 换成 Huber/L1 并**降权**（它已经把 teacher 误差压到
1.1 cm，边际收益接近零）；新增项里 `L_world` 与 `L_traj` 是唯一能让指标可见的项，
`L_heading` 与 `L_boundary` 对应实测的两大系统误差来源；同时考虑下调
`joint_contact`（占 feedback 梯度 74.5% 且与 latent 近乎正交）。

## 7. 结论 A/B/C

**A. 最可能的问题来源（按优先级）**

1. 位置目标把累积偏差 δ 塞进 target，而 δ 不在输入里、也无法在 8 帧内补回 →
   模型对 δ 不补偿（实测首帧位移 1.74→2.00 cm），损失按 δ² 增长但无可达下降方向；
   加大权重只会在不可改变的残差上加压，并把共享主干推向折中（边界跳变实测 +70%）。
2. 监督视野 32 帧 vs 评估 120–192 帧：误差超线性增长区间完全没有监督，训练 δ 量级
   （约 10 cm）远低于评估（58 cm）。
3. 朝向定价过低（实测 20° 偏航在损失上只值 0.147，而 20 cm 平移值 0.685）→
   末段 28–33° yaw 漂移 → 约 26–29 cm 位置误差，与平移漂移同量级却几乎不被惩罚。
4. 逐段重新锚定 + 帧级位置 MSE → 跨段连续性（速度）没有约束 → 边界帧步长 5.4 cm
   对比段内 0.7–0.9 cm（占末帧误差 18–29%）。
5. 与 latent 目标近乎正交（余弦 0.07）的 root 梯度与 joint_contact（占 feedback 梯度
   74.5%）一起争夺同一批参数 → 容量分配问题。

排除的两个常见猜测：root loss **并非**作用在无关分支（它就在决定 rollout 轨迹的
latent→decoder 路径上）；×30 **并未**主导梯度（feedback 下 19.4%）。

**B. 最该立刻做的诊断实验**

1. 受控 A/B：同一 checkpoint、同 schedule、同 p，只改 `root_position ∈ {0,30}`。
2. δ 冲突实测：把 GT history 人工平移 5/10/20 cm 模拟漂移，测位置项与速度项随 δ 的
   变化（预期：位置项上升、速度项不变）。
3. 训练 δ 分布统计：在反馈分支记录「生成历史相对 GT 的偏移」，与评估的 58 cm 对比。
4. oracle 条件替换（工具已有）：GT history / 自身 history × GT/预测 root × GT/预测朝向。
5. 视野实验：`primitives` 4 → 8/16（32 → 64/128 帧）。

**C. 推荐的新 loss 设计**：见第 6 节。核心是把「逐帧绝对位置」换成
「持久参考系下的位移 + 多视界累计位移 + 朝向 + 跨段连续性」，并把漂移状态显式
喂给模型使其可补偿。

## 8. 验证结果（2026-09-27 实测，`scripts/audit_drift_target_conflict.py`）

对 history 施加受控刚体偏移（沿该窗口 GT 行进方向的平移 δ，或绕最后一帧骨盆的
偏航 δψ），在**生产 loss 函数**上测量。两个 checkpoint：scratch（root_position=30，
step 9000）与 baseline（无 root 项，step 25000）；`--batches 2 --batch-size 16`。
数值为第 0 个 batch。

### 8.1 损失对漂移的定价（ideal：冻结的非自适应预测器）

预测固定为「GT 局部运动表达在**未漂移**锚点系」，target 用漂移后的锚点：

| 偏移 | 局部位置差 | root_position | joint_velocity | feature_rec | smpl_joints_rec | joint_contact | total |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| δ=0 | 0.0 cm | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0.0002 |
| δψ=10° | 0.6 cm | 0.0010 | 0.0025 | 0.0042 | 0.0022 | 0.0075 | 0.0329 |
| δψ=20° | 1.1 cm | 0.0038 | 0.0099 | 0.0154 | 0.0086 | 0.0477 | 0.1468 |
| δ=5 cm | 5.0 cm | 0.0250 | 0.0052 | 0.0004 | 0.0042 | 0.0047 | 0.0402 |
| δ=10 cm | 10.0 cm | 0.1000 | 0.0208 | 0.0018 | 0.0167 | 0.0232 | 0.1651 |
| δ=20 cm | 20.0 cm | 0.4000 | 0.0833 | 0.0071 | 0.0667 | 0.1198 | 0.6851 |
| δ=30 cm | 30.0 cm | 0.9000 | 0.1875 | 0.0160 | 0.1500 | 0.3118 | 1.5835 |
| δ=50 cm | 50.0 cm | 2.5000 | 0.5208 | 0.0443 | 0.4167 | 0.9932 | 4.5256 |

- `root_position = 30·δ²/3` **精确成立**（5 cm→0.0250，20 cm→0.4000，50 cm→2.5000），
  即上一节的物理尺度换算得到实测确认。
- **定价倒挂**：20 cm 平移使 total 增加 0.685（位置项 +0.400），而 20° 偏航只增加
  0.147（位置项 **仅 +0.0038**）——位置项上相差约 **105×**，总损失上约 **4.7×**。
  但在评估里这两者的贡献相当：xy 漂移 24–34 cm，朝向导致的漂移 26–29 cm。
  原因是 8 帧窗口内未来帧距锚点只有约 10–20 cm，朝向误差 r·δψ 显得很小，
  而它的杠杆（行进距离）要到 rollout 尺度才显现。
- `joint_contact` 同样随 δ 上升（0.005→0.99），它看的是 reactor 相对 actor 的几何。

### 8.2 训练出来的模型对漂移没有反应（model：EMA + 生产采样路径）

| δ | 模型首帧位移 | GT 首帧位移 | root_position | joint_contact |
| --- | ---: | ---: | ---: | ---: |
| 0 | 1.74 cm | 0.87 cm | 0.053 | 0.046 |
| 5 cm | 1.88 | 0.87 | 0.060 | 0.042 |
| 10 cm | 1.96 | 0.87 | 0.113 | 0.047 |
| 20 cm | 2.00 | 0.87 | 0.361 | 0.104 |
| 30 cm | 1.95 | 0.87 | 0.804 | 0.241 |
| 50 cm | 1.86 | 0.87 | 2.278 | 0.793 |

- 把 δ 从 0 加到 50 cm，模型的局部输出几乎不变（1.74→2.00→1.86 cm），
  即**它在局部首帧上完全不补偿**；位置残差 ≈ δ，损失按 δ² 上升，但没有任何
  可达的下降方向。baseline 同样（首帧 0.75→0.66 cm，略微更保守，也不补偿）。
- 含义：**加大权重只是在"不可改变的残差"上加压**，梯度只能去改那些无法区分
  漂移与非漂移输入的共享参数——这就是"把容量推向折中"的实测版本。

- 损失可见的段内局部误差在两种情形下都是 7.6–7.9 cm：**损失饱和，指标不饱和**。

### 8.4 梯度结构（grad：raw 权重 + train 模式）

| δ | 总梯度范数 | root_position 份额 | joint_contact 份额 | cos(root_position, latent) |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0.857 | 7.6% | 16.4% | **+0.277** |
| 20 cm | 1.812 | **37.8%** | **62.0%** | **−0.071** |

- baseline（无 root 项）同向：joint_contact 份额 11% → 62%，与 latent 的余弦
  始终 ≈ 0.02（正交）。
- 结论：漂移出现时，主导梯度的两项（root_position 与 joint_contact）**都与扩散主
  目标近乎正交**；位置项与 latent 的余弦甚至由正转负。所以更准确的说法是
  「×30 确实在更强地优化局部 root，但方向与主目标无关，且残差不可达」。
- **更正**：本报告早先提出的「位置项与速度项互相冲突」**不成立**——实测
  `cos(root_position, joint_velocity) = +0.554`（δ=0）/`+0.602`（δ=20 cm），
  两者方向一致。真实机制是：状态不可观测 + 残差不可达 + 朝向定价过低，而不是
  梯度方向对抗。

- 两个 checkpoint 不可比（init/曝光/curriculum/batch 全不同），第 3 节表格只用于
  误差**来源结构**分析，不用于"权重 30 使其恶化"的因果结论。
- 40 episode × 1 seed、120 帧、单一 guidance；朝向用髋轴近似，未做旋转对齐。
- 梯度审计只在 step 8500、train 模式 dropout 下、4×16 窗口上测；梯度范数不是
  损失份额，也不是因果质量贡献。
